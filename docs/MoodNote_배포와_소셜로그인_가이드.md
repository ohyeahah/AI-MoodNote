# MoodNote: 인터넷에서 돌리기 + 소셜 로그인 추가

작성: 11/10. 아래 내용 중 각 회사 사이트의 메뉴 이름과 요금은 바뀔 수 있어서, 실제로 할 때 공식 문서를 같이 확인해야 해.

## A. 인터넷에서 돌려 보기

### A-1. 오늘 바로: 임시 인터넷 주소 (팀원·폰으로 테스트)

내 맥에서 돌아가는 화면에 임시 주소를 붙여 주는 방법이야. 서버를 따로 빌리지 않아도 돼.

터미널 3개를 열어.
1. `cd software/backend` → `python3 app.py`
2. `cd software/frontend` → `npm run dev`
3. `brew install cloudflared` (처음 한 번) → `cloudflared tunnel --url http://localhost:3000`

3번 터미널에 `https://무작위글자.trycloudflare.com` 같은 주소가 나와. 폰이나 다른 사람 컴퓨터에서 그 주소를 열면 돼.

주의
- 내 맥이 켜져 있고 위 3개가 돌아가는 동안만 열려 있어. 주소는 켤 때마다 바뀌어.
- 주소를 아는 사람은 누구나 가입할 수 있어. 공개된 곳에 올리지 마.
- 개발용 서버라서 발표 시연용 QR로는 부적합해. (A-2 참고)
- Homebrew가 없으면 `brew`가 안 돼. 그럴 땐 알려 줘. 다른 방법을 안내할게.
- 같은 와이파이의 폰에서만 볼 거면 터널 없이 `http://맥의IP:3000` 으로도 열려. (맥 IP는 시스템 설정 > 와이파이 > 세부사항)

### A-2. 진짜 배포: 24시간 켜 두는 서버 (11/25 시연 QR용)

화면까지 서버 하나가 같이 내보내도록 이미 준비해 뒀어. 그래서 서비스가 1개(Flask)와 MySQL 1개면 돼.

필요한 것
- 서버를 빌려 주는 곳 (예: Railway, Render 등. 요금과 무료 한도는 직접 확인) + MySQL
- 주소가 `https://`로 시작해야 해. 빌려 주는 곳이 자동으로 붙여 줘.

순서
1. **빌드 명령**: `cd software/frontend && npm install && npm run build`
2. **시작 명령**: `cd software/backend && gunicorn app:app --bind 0.0.0.0:$PORT`
   (`pip install -r requirements.txt`도 필요해. 빌려 주는 곳이 보통 알아서 해.)
3. **환경 변수**: `.env`에 쓰던 값을 그 서비스의 환경 변수 화면에 그대로 넣어.
   `DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, JWT_SECRET_KEY, ENCRYPTION_KEY, OPENAI_API_KEY`
   그리고 `APP_ENV=production`. (이러면 테스트가 실수로 실행되지 않아.)
4. **DB 만들기**: 그 곳의 MySQL 접속 정보로 내 맥에서 `python3 setup_db_mysql.py --host 주소 --port 번호 --user 계정 --app-user moodnote_app`을 실행해.
   (외부에서 접속이 허용돼야 해. 안 되면 서비스가 주는 콘솔에서 `schema_mysql.sql`과 단어 100개를 직접 넣어야 해.)
5. 주소를 열어서 가입 → 기록 → 달력 → 그래프까지 눌러 보기.
6. 그 주소로 QR 코드를 만들어 발표 슬라이드의 `[QR code]` 자리에 넣기.

주의
- **운영 서버의 `ENCRYPTION_KEY`는 개발용과 다른 새 값으로 만들고, 따로 백업해 둬.** 잃으면 저장된 일기를 다시 읽을 수 없어.
- 운영 DB에 가짜 개발 데이터(`--seed`)는 넣지 마.
- 실제 사람들의 일기가 외부 서버에 저장되고, AI 추천을 누르면 OpenAI로도 전송돼. 동의 화면 문구가 실제 동작과 맞는지 발표 전에 한 번 읽어 봐.
- 이 작업은 역할표에서 문서진 담당으로 잡아 둔 일이야. 같이 하면 빨라.

## B. 소셜 로그인 (구글, 네이버, 카카오, 애플)

### 먼저 알아 둘 것
- 로그인 화면의 버튼 4개는 모양만 만들어 뒀고 지금은 "준비 중" 안내가 나와. 실제 연결은 아직 안 했어.
- 소셜 로그인은 **로그인 후 돌아올 주소(Redirect URI)를 각 회사에 등록**해야 해서, A-2처럼 `https://` 주소가 있어야 제대로 쓸 수 있어. 그래서 순서는 **배포 → 소셜 로그인**이야.
- 연결하려면 네 계정으로 각 회사 사이트에서 앱을 등록하고 **키(Client ID, Secret)**를 받아야 해. 내가 대신 할 수 없는 부분이야.
- 일반 회원가입(아이디, 비밀번호)은 그대로 둬. 소셜은 추가 방법이야.

### 회사별 준비물

| 회사 | 등록하는 곳 | 비용 | 알아 둘 것 |
| --- | --- | --- | --- |
| Google | Google Cloud Console → OAuth 클라이언트 ID(웹) + 동의 화면 설정 | 무료 | 앱을 "게시"하기 전에는 등록한 테스트 사용자만 로그인할 수 있어 |
| 카카오 | Kakao Developers → 앱 만들기 → 카카오 로그인 켜기 + Redirect URI | 무료 | 이메일 같은 정보를 받으려면 비즈 앱 전환이 필요해. 우리는 고유 번호만 쓰면 돼 |
| 네이버 | NAVER Developers → 애플리케이션 등록 → 네이버 로그인 + 콜백 URL | 무료 | 개발 중 상태에서는 멤버로 등록한 계정만 로그인돼. 일반 공개는 검수를 받아야 해 |
| Apple | Apple Developer Program 가입 → Services ID, 키(.p8), 도메인 확인 | **유료 (연 99달러)** | `https://` 도메인이 반드시 필요해서 localhost 테스트가 안 돼. 나중에 앱스토어에 올릴 때 다른 소셜 로그인을 넣으면 Apple 로그인도 넣어야 하는 규정이 있어 |

### 코드에서 하는 일 (내가 맡는 부분)

흐름: 버튼 누름 → 서버가 회사 로그인 화면으로 보냄 → 로그인하면 우리 서버로 돌아옴 → 서버가 회사에 확인해서 그 사람의 고유 번호를 받음 → 우리 `users`와 연결 → 로그인 토큰(JWT) 발급 → 화면으로 돌려보냄.

- DB에 `user_identities` 표 추가: `provider`(google 등), `provider_user_id`(회사가 주는 고유 번호), `user_id`. 번호만 저장하고 이메일은 저장하지 않아.
- 서버에 시작·돌아오기 주소 추가 (회사별 `start`, `callback`)
- 처음 소셜로 들어온 사람은 가입 후 **동의 화면**을 그대로 거쳐.
- 소셜로 가입한 사람은 비밀번호가 없어서, 지금의 "회원 탈퇴(비밀번호 확인)"를 다른 확인 방식으로 바꿔야 해.
- 이메일이 같다고 기존 계정과 자동으로 합치지 않아. 다른 사람 계정을 가로채는 사고를 막으려는 거야.
- 로그인 화면 버튼은 각 회사의 공식 버튼 이미지와 규정에 맞게 바꿔야 해. 지금의 G, N, 말풍선, 사과는 임시 모양이야.

### 추천 순서
1. A-2 배포로 `https://` 주소 얻기
2. Google, 카카오, 네이버 순으로 앱 등록 → 키를 받으면 내가 코드 연결 (회사마다 약 한두 시간 예상, 내 추정이야)
3. Apple은 유료 가입과 도메인 확인이 필요해서 맨 마지막, 선택 사항으로 두기
